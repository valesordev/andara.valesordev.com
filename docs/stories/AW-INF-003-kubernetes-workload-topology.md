## Context

ADR-0001 decided the shape: a `StatefulSet` with one replica at launch, owning all 64 Partitions, with
stable identity and storage because sharding later is a consumer-group rebalance rather than a
migration. This story renders that decision as a chart.

The unusual constraint is readiness. A pod that is running is not a pod that can serve players — it may
still be replaying its log tail. Readiness must reflect *simulation* readiness, or Kubernetes will send
traffic to a server that has no World yet. `AW-SRV-007` defines what ready means and sets the flag; this
story is the only thing that reads it.

**Decided 2026-09-10 (Brian): the kind cluster on Brian's box, Kubernetes v1.36.1.** The chart is written
for a real cluster and validated against v1.36.1; what that costs is recorded under Open questions.

## User story

As an operator, I want `andara-server` deployed as a chart with honest health signals, so that
Kubernetes' idea of healthy matches a player's.

## Scope

### In scope
- Helm chart `deploy/helm/andara`: `StatefulSet`, headless `Service`, `ServiceAccount`, `ConfigMap`,
  `Secret` references (never values), `PodDisruptionBudget`, `volumeClaimTemplates`, `NetworkPolicy`
  skeleton, and a `Deployment` each for `andara-projector state|redis|postgres` (`AW-SRV-017/018/019`).
- `values.schema.json` covering every server and projector configuration key, generated by
  `make values-schema` from `deploy/helm/andara/keys.yaml` — the key → `ANDARA_*` registry — held
  against `server/**/*.go` (the code is the authority for which keys exist): an `ANDARA_*` the code
  reads that the registry lacks fails `make check`; a registry entry the code does not read yet is
  warned and left out of the schema.
- Partition assignment from pod ordinal: replica `i` of `N` owns Partitions `{p : p mod N == i}`;
  `N=1` at launch.
- Probes: startup (budget covers worst-case replay), readiness (`/readyz` from `AW-SRV-007`), liveness
  (`/healthz`, process alive and tick loop not wedged).
- Snapshot volume lifecycle: retained on uninstall and scale-to-zero.
- Resource requests parametrized on measured tick cost; the measurement procedure is a make target.
- Environments `local`, `dev`, `prod` as values files; `make k8s-dry ENV=<env>` renders and validates
  all three against v1.36.1 with `kubeconform -strict`.

### Out of scope
- Service exposure, ingress, TLS, gRPC routing — `AW-INF-006`.
- Pre-stop and post-start lifecycle hooks — `AW-INF-007`. This story sets `terminationGracePeriodSeconds`
  from a value that story derives.
- Kafka, Redis, Postgres, MinIO deployment. Platform dependencies; topics are `AW-INF-004`.
- Multi-replica activation. The chart renders it; turning it on is a measured decision.

## Acceptance criteria

1. **Given** each of `local`, `dev`, `prod` **when** `make k8s-dry ENV=<env>` runs **then** manifests
   render and pass `kubeconform -strict -kubernetes-version 1.36.1`, exiting non-zero on any violation.
2. **Given** a pod whose `/readyz` returns `503 {"phase":"replay"}` **when** the readiness probe polls
   **then** the pod is not in Service endpoints; **given** `200 {"phase":"serving"}` **then** it is.
3. **Given** `helm uninstall` **when** it runs **then** the `snapshots` PVC remains, its
   `helm.sh/resource-policy: keep` annotation is present in the rendered manifest, and a subsequent
   `helm install` reattaches it by name.
4. **Given** any rendered manifest **when** grepped for the planted secret values in the values file
   **then** none appear in a ConfigMap, env literal, or chart default; secrets are `secretKeyRef` only.
5. **Given** `values.schema.json` **when** a value outside its type or range is supplied (`tickRate: "ten"`,
   `linkdeadGrace: 30`) **then** `helm template` fails naming the key.
6. **Given** an `ANDARA_*` variable read anywhere under `server/` **when** it is absent from
   `keys.yaml` **then** `make check` fails naming the variable and the file; **given** a `keys.yaml`
   entry the code does not read **then** `make check` warns naming the key and its story, and the
   schema omits it, so a values file cannot set a key the binary ignores.
7. **Given** a startup taking longer than `startupProbe.failureThreshold × periodSeconds` **when** the
   pod starts **then** it is restarted, and the default budget (600 s) exceeds `AW-SRV-007`'s measured
   worst case by at least 3×.
8. **Given** a tick loop that has not completed a tick in `sim.tick_budget_ms × 100` **when** `/livez`
   is polled **then** it returns `503 {"reason":"tick_wedged"}` and liveness restarts the pod.
9. **Given** `replicaCount: 2` **when** rendered **then** each pod's `ANDARA_SIM_PARTITIONS` env is
   derived from its ordinal via the init container, and the two sets are disjoint and complete.
10. **Given** `make measure-tick ENV=local` **when** it runs for 5 minutes against the sizing fixture
    **then** it prints p99 tick CPU and RSS, and the `prod` values file's requests are within 2× of the
    last committed measurement (`deploy/helm/measurements.yaml`), or `make check` warns.

## Interface contract

### Chart layout

```
deploy/helm/andara/
  Chart.yaml  values.yaml  values.schema.json
  templates/  statefulset.yaml  service-headless.yaml  configmap.yaml  pdb.yaml  sa.yaml
              networkpolicy.yaml  projector-deployment.yaml (×3 via range)
  keys.yaml  schema.base.yaml         # inputs to make values-schema
  files/alerts.yaml                    # Prometheus rules, also mounted by the compose stack
  measurements.yaml                    # committed output of make measure-tick (inside the chart: .Files can only read here)
deploy/helm/values/{local,dev,prod}.yaml
```

### Probes

| Probe | Path | Port | Period / threshold | Semantics |
|-------|------|------|--------------------|-----------|
| startup | `/readyz` | `http` (`ANDARA_HTTP_PORT`, 8080) | 10 s × 60 | recovery in progress; body `{"phase": "load|seek|replay|verify|serving"}` |
| readiness | `/readyz` | `http` | 5 s × 2 | 200 only when `AW-SRV-007` ready flag set **and** consumer lag < `sim.tick_budget_ms × 10` |
| liveness | `/livez` | `http` | 10 s × 3 | 200 if process alive and last tick within `tick_budget × 100`; never depends on Kafka |

Liveness must not depend on any external system: a Kafka outage is a read-only World (`AW-SRV-010`),
not a reason to restart pods in a loop.

### Ordinal → Partitions

Init container `partitions` computes `ANDARA_SIM_PARTITIONS` from `$HOSTNAME` ordinal and
`replicaCount`, writes it to a shared `emptyDir`, and the server reads it as `sim.partitions`. Formula:
`p mod replicaCount == ordinal`, over `0–63`.

### Volumes

| Claim | Mount | Size | Class | Policy |
|-------|-------|-----:|-------|--------|
| `snapshots` | `snapshot.fs_path` (`/var/lib/andara/snapshots`) | `values.snapshots.size` (20 Gi default) | `values.storageClass` | `helm.sh/resource-policy: keep`; `persistentVolumeClaimRetentionPolicy: {whenDeleted: Retain, whenScaled: Retain}` |

When `snapshot.store=s3`, the claim is still created (1 Gi) so that switching store modes is a values
change, not a topology change.

### Values (excerpt — the schema is the contract)

| Value | Type | Default | Maps to |
|-------|------|---------|---------|
| `replicaCount` | int 1–64 | `1` | StatefulSet replicas |
| `server.*` | object | per story config tables | `ANDARA_*` env, one key each |
| `server.secrets.tokenKey` / `tlsCert` / `kafkaCreds` | secretKeyRef | — | files mounted 0400 |
| `resources.requests.cpu` / `memory` | quantity | from `measurements.yaml` × 1.5 | |
| `terminationGracePeriodSeconds` | int | `90` | derived by `AW-INF-007` |
| `projectors.{state,redis,postgres}.enabled` | bool | `false` everywhere until AW-SRV-017/018/019 land | a Deployment for a binary that does not exist crash-loops |
| `pdb.minAvailable` | int | `0` at N=1 (a deploy *is* the interruption, ADR-0001) | |

### Make targets

`make k8s-dry [ENV=<env>]` (all environments when `ENV` is not given; kubeconform required, pinned
1.36.1) · `make values-schema` / `values-schema-check` (regenerate / verify from `keys.yaml`) ·
`make helm-test` (render assertions) · `make image` · `make kind-load` · `make helm-install ENV=<env>`
(idempotent `helm upgrade --install`) · `make measure-tick [DURATION=]` (AC-10; refuses until
`andara_tick_duration_seconds` exists).

## Data / state impact

Snapshot volume lifecycle across pod replacement, scale-to-zero, and uninstall: retained in every case.
Because ADR-0002 makes Kafka the authority and snapshots an RTO optimization, losing the volume is
survivable — it costs replay time, not data — and the runbook says so, because it changes how urgently
an operator treats a volume problem.

## Observability requirements

- **Metrics:** `kube_*` workload metrics scraped by the observability stack; `andara_build_info` used to
  confirm the running version and content version match intent; `andara_probe_state{probe}` gauge
  (`startup`/`readiness`/`liveness`, 0/1) exported by the server so probe flapping is visible in the
  same dashboard as ticks.
- **Logs:** pod lifecycle events (scheduled, started, killed, reason) correlated to `pod` and
  `container` labels; the server's own logs carry `trace_id`.
- **Alerts:** `AndaraServerUnavailable` (`up{job="andara-server"}` zero or absent for 2 m — the
  server's own scrape rather than `kube_*`, so one rule file is the same signal in the compose stack
  and the cluster, and a deleted StatefulSet has no series to be zero) and `AndaraServerCrashLooping`
  (restarts > 3 in 10 m), both tied to `docs/specs/slo/world-write-availability.md`, shipped as a
  ConfigMap from `files/alerts.yaml` and mounted by the compose Prometheus; runbooks
  `docs/runbooks/server-unavailable.md` and `docs/runbooks/server-crashlooping.md` ship here.

## Test plan

- **Unit:** `scripts/helm_test.py` (`make helm-test`) for AC-3, AC-4, AC-5, AC-9 and the probe
  contract, over `helm template` output — `helm unittest` is a plugin that cannot be pinned like the
  `./bin` tools, and the same assertions in Python match the repo's other checks; `keys.yaml`-vs-code
  check and pending-key warn (AC-6) in `scripts/values_schema.py`.
- **Integration (kind, CI):** install with a fixture log needing 30 s of replay, assert endpoints empty
  until `serving` (AC-2); wedge the tick via a test hook, assert restart (AC-8); uninstall/reinstall
  asserting PVC reuse (AC-3).
- **Manual/operator:**
  ```
  make k8s-dry ENV=prod                                  # expect: renders clean, kubeconform summary
  make helm-install ENV=local && kubectl get sts andara  # expect: 1/1 after recovery, not before
  kubectl get pvc -l app=andara                          # expect: snapshots-andara-0 Bound
  ```

## Open questions

- **Resolved 2026-09-10 (Brian): kind on Brian's box, v1.36.1.** The kind "cluster" is four containers
  on one machine. RF=3 with `min.insync.replicas=2` is three replicas on one disk, so
  `slo/recovery.md`'s zero-RPO is a claim about one machine until this moves. The chart is **not**
  softened to match; ADR-0002 carries the note under `Revisit when`.
- `[ASSUMPTION]` Environments are `local`, `dev`, `prod`. Adding staging later is cheap.
- `[ASSUMPTION]` Resource requests are parametrized on `measurements.yaml` rather than guessed;
  `AW-SRV-002` produces the first measurement and this story's `make measure-tick` records it. Until
  then the file carries a placeholder flagged `measured: false`, which `make check` warns on.
